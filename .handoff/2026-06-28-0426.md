# Session Handoff — 2026-06-28-0426

## Project
`opencode-model-failover` — OpenCode plugin for automatic model failover.

## What was done

### Test: failover on credit exhaustion (real scenario)
- User switched to model without credits → `session.error` with "requires more credits"
- Plugin classified as permanent error (matches "credit balance"/"billing" patterns in `PERMANENT_ERROR_PATTERNS`)
- Failover triggered: aborted session, tried `opencode-go/deepseek-v4-flash` fallback
- **Success**: `session.next.model.switched` fired, streaming response started, `fallback succeeded` logged
- Full log timeline documented in conversation

### Bug found: cooldown blocking failover on manual model switch
- After successful failover, user manually switched back to broken model
- 30s session cooldown from previous failover was still active → failover skipped
- User saw "retrying in 16h 45m attempt #1" with no intervention
- Log showed: `session ses_XXX in cooldown, skipping failover`

### Fix iteration 1: Reset cooldown on session.next.model.switched
- Added handler for `session.next.model.switched` event → resets `cooldownUntil = 0`
- Also added `sessionID` to all `session.status` log lines

### Fix iteration 2: Remove session-level cooldown entirely (chosen)
- User noted cooldown can also block automatic retries, not just manual switches
- **Decision**: Eliminate session-level cooldown, rely only on model-level cooldown (60s per failed fallback model)
- Removed: `cooldownUntil`, `retryCount` from `SessionState`
- Removed: `isCooldownActive()`, `activateCooldown()`, `SESSION_TTL_MS`
- Removed: `session.next.model.switched` handler (no longer needed)
- Simplified: `cleanupStaleSessions()` → `cleanupStaleModelCooldowns()` (only modelCooldowns)
- Bundle size: 9.39 KB → 8.47 KB (9.8% smaller)
- Line count: 363 → 320

### Build & deploy
- `bun run typecheck` — passed
- `bun run build` — success (8.47 KB)
- `bun run deploy` — deployed to `~/.config/opencode/plugins/model-failover.js`

## Current state
- No session-level cooldown: every error triggers failover immediately
- Model-level cooldown (60s): prevents retrying a fallback model that recently failed
- `failoverInProgress` guard: prevents concurrent failover executions
- Sessions cleaned up on `session.deleted` events
