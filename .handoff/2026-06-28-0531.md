# Session Handoff — 2026-06-28-0531

## What was done

### Bug: failover model not persisting for next user message
- After successful failover, the "Continue" re-prompt used the fallback model, but subsequent user messages went back to the original broken model
- Root cause: `session.update` API only supports `title`, not `model` — the old code's try/catch silently swallowed this
- SDK limitation: `Session` type has no `model` field; no hook exists to intercept user prompts before LLM call; no TUI API to change model selector programmatically

### Fix: toast notification + session title marker
- **Toast**: After successful failover, `client.tui.showToast` with title "Failover", message "Switched to {model}", variant "warning"
- **Session title**: `client.session.get` → read title → strip existing `[failover: ...]` marker → append `[failover: {model}]` → `client.session.update`
- Replaced the old dead `session.update` with model field (which silently failed)
- Bundle size: 9.81 KB (up from 8.47 KB due to new code)
- `bun run typecheck` — passed
- `bun run build` — success
- `bun run deploy` — deployed to `~/.config/opencode/plugins/model-failover.js`

## Current state
- No session-level cooldown: every error triggers failover immediately
- Model-level cooldown (60s per config): prevents retrying a fallback model that recently failed
- `failoverInProgress` guard: prevents concurrent failover executions
- Sessions cleaned up on `session.deleted` events
- Toast + title marker on successful failover
