## What was done

### Bug: user cannot manually change model after failover
- After successful failover, the `chat.message` hook **unconditionally** overrode the model on every user message
- `input.model` from SDK tells the user's currently selected model (`chat.message` input has `model?: { providerID, modelID }`)
- `session.error` event does NOT carry model info (confirmed via SDK types)
- However `chat.message` fires **before** the LLM call, so we can track `input.model` before an error occurs

### Fix: conditional override via userModel tracking
- Added `userModel`, `originalModel`, `failoverModel` to `SessionState` (consolidated into single state object, removed separate `failoverModels` map)
- `chat.message` stores `userModel` from `input.model` on every message
- `executeFailover` snaps `originalModel` from `s.userModel` at failover time
- `chat.message` only overrides if `input.model` matches `originalModel` → user hasn't manually changed
- If user changes model via `/models` (input.model ≠ original) → clears failover state, respects user choice
- Removed rogue `/home/alejo/.config/opencode/plugins/model-failover.json` (orphan config)
- `bun run typecheck` — passed
- `bun run build` — success (10.43 KB)
- `bun run deploy` — deployed
